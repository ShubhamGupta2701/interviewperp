Database Systems: B+ Trees and Database Indexes

Focus: fast disk-oriented lookup, ordered scans, and the difference between B-trees and B+ trees.

1. Core Concepts

A B+ tree is a height-balanced, multiway search tree commonly used for database indexes. Each node holds many sorted separator keys, so a single page read rules out a large range of values.

  • Fan-out: number of children an internal node can have. High fan-out keeps the tree shallow.
  • Internal node: stores separator keys and child pointers; it guides the search.
  • Leaf node: stores every search key and a row pointer (or the row itself in a clustered index).
  • Balanced: every leaf has the same depth, giving predictable lookup cost.
  • Linked leaves: adjacent leaf pages point to each other, enabling efficient range scans.
B-tree vs. B+ tree
A B-tree may store records in internal nodes. A B+ tree stores data entries only at leaves, which improves fan-out and makes ordered scanning simple.

2. Definitions, Formula & Algorithm

With fan-out F and N indexed entries, a rough height estimate is:

height ≈ ceil(log_F(N))

That logarithm matters because storage pages are expensive compared with CPU comparisons. A fan-out of 100 can index about one million entries in roughly three levels: root → internal page → leaf page.

Lookup algorithm:

node = root
while node is not a leaf:
  find the first separator greater than the target
  follow the child just to its left
search the target key in the leaf

Insertion descends to a leaf, adds the key in sorted order, and splits a full page. The split’s separator is propagated upward; if the root splits, a new root is created. Deletion may redistribute entries with a sibling or merge underfull pages.

3. Teaching Explanation

Think of a B+ tree as a library directory. The first sign tells you the shelf range, the next sign narrows it to one shelf, and the shelf itself contains the books in order. A binary tree would need many more levels because each node has only two choices.

Databases choose node sizes near a disk or memory page. Reading one page then provides dozens or hundreds of key comparisons in RAM. This design minimizes the costly part: page reads, not comparisons.

4. Examples

Example 1 — Point lookup

To find customer ID 42, internal separators choose one child at each level until its leaf page is reached. The leaf finds 42 and returns its row pointer. A shallow tree means only a few page reads.

Example 2 — Range query

For WHERE created_at BETWEEN A AND B, first find A’s leaf. Then follow leaf-to-leaf links, returning keys until B. The tree does not restart a root-to-leaf search for every row.

Example 3 — Leaf split

If a full leaf receives key 37, split it into two sorted leaves and insert a separator into the parent. The tree remains balanced because the new leaves stay at the same depth.

5. Common Misconceptions

  • “An index always makes a query faster.” It can add write cost and may be worse than a table scan for low-selectivity queries.
  • “B+ tree search is O(log n), so disk layout is irrelevant.” Fan-out and page locality determine the number of I/Os, the practical cost.
  • “A B+ tree is a binary search tree.” It is a multiway tree; its many children are the reason it is shallow.
  • “Range scans need repeated lookups.” Linked leaf pages make a sequential scan after the first lookup possible.

6. Exam & Interview Points

  • Explain why high fan-out minimizes disk I/O and why all leaves have equal depth.
  • Contrast a point lookup with a range scan; mention linked leaves for the latter.
  • State the usual complexity as O(log_F N) page traversals, plus leaf work.
  • Know the split path for insertion and the redistribute-or-merge path for deletion.
  • Connect indexes to trade-offs: faster reads, more storage, and slower inserts/updates/deletes.

7. Practice Questions

Q1. Why are B+ trees preferred over binary search trees for disk-based indexes?

Answer: Their high fan-out makes them much shallower, so lookups use far fewer page reads.

Q2. How does a B+ tree execute a range scan efficiently?

Answer: It finds the starting key once, then follows linked leaf pages in sorted order until the range ends.

Q3. What happens when a full leaf receives a new key?

Answer: The leaf splits, and a separator is inserted into the parent; the split can propagate up to a new root.

Professor's 60-second recap

A B+ tree is a page-friendly, balanced, multiway index. Internal pages route searches; leaves hold all data entries and connect in order. High fan-out keeps lookups shallow, while linked leaves make ranges efficient.
