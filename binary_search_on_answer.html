Data Structures & Algorithms: Binary Search on Answer

Focus: solve optimization problems by searching a monotonic answer space.

1. Core Concepts

Binary search on answer is a technique for finding the smallest or largest value that satisfies a feasibility condition. Instead of searching an array, search the possible answer values.

  • Answer space: every candidate value between a proven lower and upper bound.
  • Feasibility predicate: can(x), which answers whether candidate x is achievable.
  • Monotonicity: once can(x) becomes true (or false), it stays true (or false) in the relevant direction.
  • Boundary: the first true value for a minimum problem, or the last true value for a maximum problem.
Recognition test
If the question asks for a minimum/maximum and you can check a guessed answer greedily in linear or near-linear time, look for a monotonic predicate.

2. Algorithm & Formulas

For the smallest feasible answer, maintain an inclusive range [lo, hi]. If mid works, keep it and search left; otherwise search right.

while lo < hi:
  mid = lo + (hi - lo) // 2
  if can(mid): hi = mid
  else: lo = mid + 1
return lo

Typical complexity is O(log R × C), where R = hi - lo + 1 is the answer range and C is the cost of one feasibility check. Use lo + (hi - lo) // 2 to avoid integer overflow in fixed-width languages.

3. Teaching Explanation

Imagine asking: “Can I finish the work in x days?” If the answer is yes for 10 days, it is also yes for 11 days. The answers have a boundary: false, false, false, then true forever. Binary search locates that boundary without testing every day.

The hard part is not the loop. It is proving the bounds, writing a correct feasibility check, and explaining why the predicate is monotonic.

4. Examples

Example 1 — Minimum ship capacity

Given package weights and a deadline, guess a capacity. Greedily pack packages in order and count days. Capacity too small means “false”; capacity large enough means “true.” Search from the heaviest package to the total weight.

Example 2 — Minimum eating speed

For piles and H hours, can(k) computes Σ ceil(pile / k). If the hours fit at speed k, they also fit at any larger speed. Find the first feasible speed.

Example 3 — Maximize minimum distance

For sorted stall positions, guess a distance d and greedily place each next item at least d away. If placement succeeds, try a larger distance; otherwise reduce it. Search for the last feasible distance.

5. Common Misconceptions

  • “Binary search requires a sorted array.” The answer space must be monotonic; it does not have to be an input array.
  • “The predicate can be any check.” Without monotonicity, binary search can skip the correct answer.
  • “Use 0 and 109 for every bound.” Tight, proven bounds reduce bugs and make overflow less likely.
  • “A greedy check must produce the optimal construction.” It only needs to correctly decide feasibility for the guessed answer.

6. Exam & Interview Points

  • State whether you seek the first true or last true value.
  • Derive bounds from the problem: lower bound often comes from a mandatory minimum; upper bound from a simple valid solution.
  • Explain the invariant: the answer remains inside [lo, hi].
  • Check division ceilings carefully: ceil(a / b) = (a + b - 1) // b for positive integers.
  • Use 64-bit integers when sums or products can exceed 32-bit range.

7. Practice Questions

Q1. What must be true for binary search on answer to work?

Answer: Candidate answers must have a monotonic feasibility predicate, plus valid lower and upper bounds.

Q2. A feasibility check costs O(n) and the answer range has R candidates. What is the total complexity?

Answer: O(n log R).

Q3. For a minimum feasible value, what happens when can(mid) is true?

Answer: Keep mid as a candidate and search the left half by setting hi = mid.

Professor's 60-second recap

When an optimization question has a monotonic yes/no answer, binary-search the answer rather than the data. Prove the range, write can(x), preserve the boundary invariant, and report O(log range × check cost).
