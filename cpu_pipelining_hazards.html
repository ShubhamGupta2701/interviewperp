Computer Architecture: CPU Pipelining and Hazards

Focus: overlapping instruction work, measuring throughput, and preserving correctness around dependencies and branches.

1. Core Concepts

Pipelining divides instruction execution into stages so different instructions can occupy different stages at the same time. A classic five-stage pipeline is IF → ID → EX → MEM → WB: fetch, decode/register read, execute, memory access, and write-back.

  • Latency: time for one instruction to travel from its first stage to completion.
  • Throughput: completed instructions per unit time; ideally one instruction completes each clock cycle after the pipeline fills.
  • Structural hazard: two stages need the same hardware resource in one cycle.
  • Data hazard: an instruction needs a value that an earlier instruction has not produced yet.
  • Control hazard: the next instruction is unknown because a branch or jump changes control flow.
Key idea
Pipelining improves throughput, not the amount of useful work in an individual instruction. Stalls, forwarding logic, and branch prediction exist to keep overlapping work correct and productive.

2. Definitions, Formula & Algorithm

For n instructions in an ideal k-stage pipeline with cycle time T:

non-pipelined time = n × k × T
pipelined time = (k + n − 1) × T
ideal speedup = (n × k) / (k + n − 1)

For a long stream, the ideal cycles per instruction (CPI) approaches 1. Real pipelines add penalties:

CPI = 1 + stall cycles per instruction
execution time = instruction count × CPI × clock-cycle time

Typical response to a read-after-write dependency:

if consumer needs a value before it is written back:
  if a later pipeline register already holds the value, forward it to the consumer
  otherwise insert a bubble (stall) until the value is available

3. Teaching Explanation

Think of a pipeline as a five-station assembly line. One instruction is being fetched while another is decoded, a third is calculated, and so on. The first finished unit still takes five station-times, but after the line is full, a finished unit can leave every station-time.

The tricky cases are when the line cannot safely continue. A consumer might arrive before its producer’s result, two jobs might demand one machine, or a branch might send the line down the wrong path. The processor either supplies the needed result early, waits, duplicates/separates a resource, or discards speculative work after discovering the correct path.

4. Examples

Example 1 — Pipeline timing

With five stages and 20 instructions, a non-pipelined design takes 20 × 5 = 100 cycles. An ideal pipeline takes 5 + 20 − 1 = 24 cycles, assuming balanced stages and no hazards.

Example 2 — Data forwarding

add r1, r2, r3 followed by sub r4, r1, r5 has a RAW dependency on r1. Forwarding can send the add result directly from a later stage to the subtract’s execute stage instead of waiting for register write-back.

Example 3 — Load-use stall

lw r1, 0(r2) followed immediately by add r3, r1, r4 often needs one bubble even with forwarding: the loaded value arrives only after the memory stage, too late for the next instruction’s execute stage.

5. Common Misconceptions

  • “A five-stage pipeline makes every instruction five times faster.” Its single-instruction latency is still roughly five stages; the gain is steady-state throughput.
  • “Forwarding removes every data hazard.” It handles many register dependencies, but a load-use pair can still require a stall.
  • “Branches only cost time when taken.” Any unresolved branch can force a stall or misprediction recovery because the next fetch address is uncertain.
  • “More pipeline stages always mean higher performance.” Deeper pipelines can raise clock frequency but also add latch overhead and increase misprediction penalties.

6. Exam & Interview Points

  • Draw the five stages and distinguish latency from throughput.
  • Classify hazards as structural, data, or control; RAW is the common in-order data hazard.
  • Explain forwarding versus stalling, including why a load-use dependency is special.
  • Use CPI = 1 + stall cycles per instruction to connect hazards to execution time.
  • State that branch prediction improves average performance but needs recovery on a wrong prediction.

7. Practice Questions

Q1. Why can a pipeline complete nearly one instruction per cycle even though an instruction uses several stages?

Answer: Different instructions occupy different stages concurrently; after fill, one can leave the final stage each cycle.

Q2. What is the difference between forwarding and a stall?

Answer: Forwarding routes a produced value directly to a consumer before register write-back; a stall inserts time when the value is not ready soon enough.

Q3. A program executes 1,000 instructions with CPI 1.2 and a 2 ns clock. What is its execution time?

Answer: 1,000 × 1.2 × 2 ns = 2,400 ns, or 2.4 μs.

Professor's 60-second recap

A pipeline overlaps instruction stages to increase throughput. Hazards are correctness conflicts caused by resources, dependencies, or uncertain control flow. Forwarding, stalls, and branch prediction trade hardware complexity for a CPI closer to one.
