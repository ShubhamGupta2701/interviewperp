Data Structures & Algorithms: Union-Find

Focus: maintaining disjoint groups, fast connectivity checks, and the two optimizations that make it nearly constant time.

1. Core Concepts

Union-Find, also called Disjoint Set Union (DSU), maintains a partition of elements into non-overlapping sets. It is ideal when sets only merge and you repeatedly need to ask whether two items are connected.

  • find(x): returns the representative (root) of the set containing x.
  • union(a, b): merges the sets containing a and b.
  • Connected: find(a) == find(b).
  • Parent array: each element points toward a root; a root points to itself.
Key idea
DSU does not store every path in a graph. It stores just enough structure to answer “same component?” while edges are being added.

2. Definitions, Formula & Algorithm

Initialize parent[x] = x and size[x] = 1 for every element. Use two optimizations:

find(x): if parent[x] != x: parent[x] = find(parent[x]) return parent[x] union(a, b): ra, rb = find(a), find(b) if ra == rb: return false attach the smaller tree under the larger tree return true

Path compression makes every visited node point closer to the root. Union by size/rank keeps trees shallow by attaching the smaller tree below the larger.

m operations on n elements: O(m α(n)) amortized α(n) = inverse Ackermann function, effectively < 5 in practice

3. Teaching Explanation

Imagine student clubs. At first, each student is their own club. When two clubs collaborate, you join their leaders. To see whether two students are in the same club, follow each student’s leader chain until reaching the leader at the top.

Without care, those chains can become long. Union by size avoids making a large club report through a tiny club. Path compression is like giving everyone you met the leader’s direct phone number. Future checks become extremely fast.

4. Examples

Example 1 — Connected components

Start with {1}, {2}, {3}, {4}. After union(1, 2) and union(2, 3), find(1) == find(3), so 1 and 3 are connected. Element 4 is still separate.

Example 2 — Detecting a cycle

Process undirected edges (1,2), (2,3), (1,3). The first two unions merge components. For (1,3), both endpoints already share a root, so that edge closes a cycle.

Example 3 — Kruskal’s MST

Consider edges in increasing weight. Add an edge only when its endpoints have different roots, then union them. DSU prevents adding an edge that would form a cycle.

5. Common Misconceptions

  • “DSU can answer any graph path query.” It answers component membership, not the actual path, distance, or a route between nodes.
  • “find is always O(1).” A single unoptimized find can be linear; the near-constant bound requires both standard optimizations amortized over operations.
  • “Union-Find supports removing edges naturally.” Ordinary DSU handles merges well but not splits; dynamic connectivity needs different techniques.
  • “Rank means the set size.” Rank is usually a height bound; size is a count. Either can guide union, but they are not the same value.

6. Exam & Interview Points

  • State the invariant: roots represent sets, and two elements share a set exactly when their roots match.
  • Explain why path compression belongs inside find, not as a separate pass.
  • Use DSU for incremental connectivity, cycle detection in undirected graphs, and Kruskal’s algorithm.
  • Remember that successful union calls reduce the number of components by one.
  • Give the amortized complexity as O(α(n)), commonly treated as constant in practice.

7. Practice Questions

Q1. Why does find(a) == find(b) determine connectivity in DSU?

Answer: Each set has exactly one root representative, so matching roots mean the elements belong to the same set.

Q2. What changes when path compression runs on find(x)?

Answer: Nodes along x’s path are rewired to point directly to the root, making later finds shorter.

Q3. How does Kruskal’s algorithm use DSU?

Answer: For each lightest remaining edge, it adds the edge and unions its endpoints only if their roots differ, thereby avoiding cycles.

Professor's 60-second recap

Union-Find represents each connected component as a rooted tree. find identifies a component and union merges two of them. Path compression plus union by size/rank makes a long sequence of operations effectively constant time.
