Operating Systems: Virtual Memory and Page Replacement

Focus: address translation, page faults, locality, and why replacement policies affect performance.

1. Core Concepts

Virtual memory lets each process use a private, contiguous virtual address space while the operating system maps its pages to physical-memory frames. Pages not currently in RAM can reside on secondary storage.

  • Page: a fixed-size chunk of virtual memory.
  • Frame: a fixed-size chunk of physical memory that holds one page.
  • Page table: maps a virtual page number to a frame number and protection/status bits.
  • TLB: a small cache of recent page-table translations.
  • Page fault: an exception raised when a referenced valid page is absent from RAM.
Key idea
Virtual memory is an abstraction, not a promise that every virtual address is backed by RAM. The mapping makes memory protection and controlled sharing possible too.

2. Definitions, Formula & Algorithm

For a virtual address with page size 2^p bytes:

virtual address = (virtual page number, offset)
physical address = (frame number, offset)

The offset is unchanged by translation. If a TLB hit takes time t_TLB, a memory access takes t_M, and the TLB hit ratio is h, a simple effective access-time model is:

EAT = h × (t_TLB + t_M) + (1 − h) × (t_TLB + 2t_M)

Page-fault handling:

trap to the OS
validate the address; abort if invalid
find a free frame or choose a victim page
write back a dirty victim if needed
read the demanded page into the frame
update the page table and TLB
restart the faulting instruction

3. Teaching Explanation

Imagine a desk (RAM) and a large filing cabinet (disk). A process sees a huge, neatly numbered collection of folders, but only the folders it is using need to be on the desk. The page table is the index saying where each folder currently lives.

When a needed folder is in the cabinet, the interruption is a page fault. Bringing it to the desk is far slower than an ordinary memory access, so the OS relies on locality: programs tend to reuse nearby data and recently used code.

4. Examples

Example 1 — Address translation

With 4 KiB pages, the offset uses 12 bits. If virtual page 7 maps to frame 42, an address in page 7 keeps its 12-bit offset and becomes an address in frame 42 at that same offset.

Example 2 — Demand paging

A program calls a function on a code page that is not in RAM. The CPU faults, the OS loads that page, records its frame in the page table, and restarts the instruction. The program normally does not need special code for this.

Example 3 — Choosing a victim

With three frames and reference string 1, 2, 3, 1, 4, LRU evicts page 2 when 4 arrives: page 1 was just reused, while 2 was least recently used.

5. Common Misconceptions

  • “A page fault is always an error.” It is expected under demand paging; an invalid address is the error case.
  • “Virtual memory is just extra RAM.” It also provides isolation, permissions, and a per-process address-space abstraction.
  • “More frames can never cause more faults.” Some policies, notably FIFO, can show Belady’s anomaly.
  • “The TLB stores data bytes.” It caches translations, not the contents of pages.

6. Exam & Interview Points

  • Walk through virtual-address translation and state why the offset does not change.
  • Contrast a TLB miss (often a page-table walk) with a page fault (disk I/O and OS handling).
  • Compare FIFO, LRU, and the theoretical optimal replacement policy.
  • Explain temporal and spatial locality as the reason paging works well in practice.
  • Recognize thrashing: excessive page faults leave the CPU waiting for storage rather than useful work.

7. Practice Questions

Q1. What part of a virtual address remains unchanged during paging translation?

Answer: The page offset; only the virtual page number is replaced with a physical frame number.

Q2. Why is a high TLB hit ratio important?

Answer: It avoids extra page-table memory accesses on most loads and stores, reducing effective access time.

Q3. What must happen before a faulting instruction can resume?

Answer: The OS must validate the reference, place the page in a frame, update translation state, and then restart the instruction.

Professor's 60-second recap

Paging maps virtual pages to physical frames while keeping the offset intact. The TLB makes common translations fast; page faults are expensive, so locality and a sensible replacement policy are central to performance.
